# Journey Atlas UX and bug audit — 12 September 2026

The strongest next step toward an Apple-like experience is reliable state: edits that stay saved, navigation that preserves context, controls that always do what they say, and graceful handling of incomplete trips. The site already has a distinctive visual identity, useful map/photo integration, and substantially improved mobile navigation. Several integration defects still interrupt that experience.

**Baseline and scope.** This audit was reconciled against deployed commit [`e937dade`](https://github.com/gravelcycles/travels/commit/e937dade3a4de0284d69d1759a558b66d7c4253f), whose [Pages deployment succeeded](https://github.com/gravelcycles/travels/actions/runs/34580328436). The working checkout was 40 commits behind that revision and contained unrelated changes. An isolated copy of the deployed source was used to avoid reporting already-fixed bugs or disturbing ongoing work. All source links below point to that immutable revision.

- Browsed the public catalog, family introduction, maps, journal, albums, representative full photos, photo-location navigation, and Replay.
- Exercised all 14 family journal days, the five samples' 30 days, and stepping through all 14 family Replay chapters. This checks rendered day/chapter navigation; it is not a full real-time watch of every route animation or inspection of all 99 family photos.
- Played the group sample's video and advanced into the next day's album. Checked sample switching and the newer group/media interface.
- Checked representative layouts at 1280 × 800, 834 × 1112, 390 × 844, 320 × 568, and 844 × 390. Not every screen was tested at every size.
- Inspected current Studio Photos, planner, route operations, and Day copy. Created a disposable three-day trip through Studio, edited a day title, and saved it. Previewed empty and round-trip fixtures. All test content and persistence experiments stayed in isolated temporary copies.
- Current release: **272 tests pass; build succeeds with byte-identical public output.** The older working tree also passed its 202 tests.

Evidence labels: **Browser** = observed on the live site or an isolated copy of the current release; **Reproduced** = current implementation executed with controlled inputs/responses; **Source** = direct implementation evidence, without a live failure simulation. Guest authentication, actual device touch/pinch, screen-reader operation, and real slow/offline networks were not fully exercised. No real trip content, product code, publishing state, credentials, or unrelated working changes were modified.

An out-and-back with multiple legs can take the same branch. **Browser + Reproduced.** [routeLabel](https://github.com/gravelcycles/travels/blob/e937dade3a4de0284d69d1759a558b66d7c4253f/dist/assets/app.js#L382) | Valid partial trip data always renders. **Performance, accessibility, and recovery**

- **Q1 · P2 · Reproduced: invisible mobile neighbors fetch as high-priority full photos.** With data saving and 2G flags, selecting a middle photo still requests both full-size neighbors. These calls bypass the protected-photo loader's speculative safeguards. Opening a thumbnail grid can also leave full-size work running behind it. Route neighbor warming through the shared queue, prioritize the selected image, and defer unnecessary full images in grid mode. This is a reproduced request-priority defect, not a measured claim about seconds of live delay. [neighbor loading](https://github.com/gravelcycles/travels/blob/e937dade3a4de0284d69d1759a558b66d7c4253f/dist/assets/mobile-ux.js#L227), [loader integration](https://github.com/gravelcycles/travels/blob/e937dade3a4de0284d69d1759a558b66d7c4253f/dist/assets/app.js#L1970).
- **Q2 · P2 · Reproduced: recovered map still says unavailable.** An error followed by successful map load leaves the banner visible. Clear stale errors on recovery; give map failures a consistent Retry action across map surfaces. Prefer user-facing wording such as “Map unavailable.” [error](https://github.com/gravelcycles/travels/blob/e937dade3a4de0284d69d1759a558b66d7c4253f/dist/assets/app.js#L594), [successful load](https://github.com/gravelcycles/travels/blob/e937dade3a4de0284d69d1759a558b66d7c4253f/dist/assets/app.js#L541).
- **Q3 · P2 · Computed from current CSS: secondary text is too faint.** `#687b7e` on `#fbfaf6` yields 4.257:1 for small catalog/day metadata, below the 4.5:1 normal-text threshold. Darken the shared muted token and verify actual backgrounds. [metadata style](https://github.com/gravelcycles/travels/blob/e937dade3a4de0284d69d1759a558b66d7c4253f/dist/assets/styles.css#L76), [W3C threshold](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

A pending response can prevent the journal/entry from becoming useful. Bundle a pinned dependency or load maps independently with bounded recovery. A real stalled-CDN browser session was not simulated. [dependency order](https://github.com/gravelcycles/travels/blob/e937dade3a4de0284d69d1759a558b66d7c4253f/content/templates/journey.html#L260).
- **Q5 · P3 · Source: some accessible identities remain incomplete.** Name the About dialog and expose the selected Studio mode semantically, alongside its visual active state. Consider a skip-to-journal/map action. [dialog](https://github.com/gravelcycles/travels/blob/e937dade3a4de0284d69d1759a558b66d7c4253f/content/templates/journey.html#L137), [Studio mode](https://github.com/gravelcycles/travels/blob/e937dade3a4de0284d69d1759a558b66d7c4253f/studio/studio.js#L1056).

**Missing features with the clearest payoff**

1. **Recoverable authoring.** Autosaved recovery drafts, visible save state, restore points, and a review/reapply flow for revision conflicts. Allow validated deletion/reassignment of places, legs, and drafts with Undo. Begin with B1/C4/C5 before adding more editing modes.
2. **Share and resume the exact moment.** Copy links for the current day/photo/map chapter; restore the selected day/photo and paused Replay position after reload or return. Include a clear Start over action. Fix V1/V2 first so these affordances can be trusted.
3. **Batch photo work.** Multi-select, bulk day assignment/hide/restore, search by filename/date, and faster ordering. This is a meaningful reduction in work for a 99-photo trip. Keep captions optional.
4. **A clear ready-to-share handoff.** Show what is saved locally, what is live, and what still needs review: unassigned media, provisional routes, or missing destinations. Offer Preview and an agent publishing handoff. Publishing and routing setup are intentionally agent-operated; the missing element is a clear creator-facing status/review surface, not an unapproved automatic Publish button.
5. **Private video intake.** Current playback and public URL authoring work. Uploading/transcoding private family clips with poster previews, progress, cancel/retry, and the same access model as photos remains useful missing work; it is already tracked as W07. Do not describe video playback or group travel as absent.
6. **A labeled Replay timeline.** Let people recognize and seek a day/chapter by its title, route, and progress rather than guessing along a largely unlabeled slider. Preserve the current map-only direction and stable controls.

**Visual and interaction polish**

Keep the existing atlas identity and shared framework. Reduce repeated Journey Atlas/trip headings on desktop, quiet utility controls, and give each screen one clear primary action. Standardize Back/Close/Done meaning and terminology around Replay, day details, and albums. Preserve context and focus across transitions; keep animations interruptible.

Studio would benefit from progressive disclosure: essentials for the current trip first, with empty group/video/advanced editorial sections secondary. Native date/time-zone/place picking, identifiable photo choices, and plain-language errors would reduce technical form work. At 320 × 568, the introduction's primary actions fall below the initial viewport; tune cover/title spacing if making the entry immediately actionable on short phones is a goal. This is layout polish, not an unreachable-control claim.

**Suggested implementation sequence**

1. **Protect work and valid data:** B1, B2, C4, C5, C6. Add regression cases using actual user actions and delayed responses.
2. **Make navigation and recovery consistent:** V1–V5, C1–C3, Q2. Check desktop, phone, empty content, and public/protected media.
3. **Remove misleading work and refine quality:** C7, V6/V7, Q1/Q3–Q5, then visual hierarchy and labeled seeking.
4. **Add useful capability:** recoverable drafts/conflict review, batch editing, share/resume, publication readiness, private video intake.

For each shared behavior change, keep one implementation and verify the family trip, at least one sample, and a fresh draft. Add a compact real-browser suite for save-in-flight, Back/reload, empty-day actions, responsive hitbox overlap, and failure/recovery paths. Passing unit/template tests alone did not catch the defects above.

**Already improved; do not regress or reopen as old bugs.** Current keyboard day selection moves focus to the journal heading; clustered markers offer explicit day choices; phone photo/grid Back and Forward work; the sample/group selection is reflected in the URL; mobile Replay controls remain anchored in the checked portrait/landscape states. The newer planner preview/save ownership guards fix the older cross-trip response race. Current focus-ring contrast is improved. Map-only Replay is deliberate, and videos/groups already exist. Earlier audits and the older working checkout contain superseded behavior.

This is an audit deliverable. No product fixes or deployments were performed.
